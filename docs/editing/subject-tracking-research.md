# Subject tracking source review

The investigation used pinned source checkouts. OpenCV, SAM 2 and ByteTrack were reused from the Phase 1 clones. TAPNet, Cutie, CoTracker and SAM 3 were separately cloned. OpenCV's small VitTrack model was evaluated from the official pinned distribution using the existing Windows OpenCV wheel.

| Project and code inspected | Tracking and loss behavior | Runtime, license and decision |
| --- | --- | --- |
| OpenCV `7a8d99e6b225`. `featureselect.cpp`, `lkpyramid.cpp`, `ptsetreg.cpp`, `lk_track.py` and its regression test. | Shi–Tomasi ranks minimum local eigenvalues and enforces spacing. Pyramidal LK provides per-point status and a texture threshold. The demo repeats flow in reverse and removes inconsistent points. RANSAC fits a bounded similarity transform to the surviving points. A camera move can shift all points together. A local consensus and live-pixel checks are the subject signal. The existing reframe heatmap already estimates global translation for motion-only framing. | Apache-2.0. No new weights or GPU. Adopt the installed primitives and implement explicit loss, geometry and identity checks. Replay only the selected range with bounded frame and template buffers. [Feature selection](https://github.com/opencv/opencv/blob/7a8d99e6b2253d32d8746f74a8f9805eee9c0c52/modules/features/src/featureselect.cpp), [LK](https://github.com/opencv/opencv/blob/7a8d99e6b2253d32d8746f74a8f9805eee9c0c52/modules/video/src/lkpyramid.cpp), [RANSAC](https://github.com/opencv/opencv/blob/7a8d99e6b2253d32d8746f74a8f9805eee9c0c52/modules/geometry/src/ptsetreg.cpp) |
| TAPIR and TAPNext++ `ceedd60bb9f6`. `tapir_model.py`, `tapnextpp/votsp2026/model.py` and `tracker.py`, and the inference manifests. | TAPIR matches a query across frames and refines trajectories and occlusion estimates. Its causal variant caches temporal state. TAPNext++ carries recurrent state and emits per-query visible booleans with positions. The VOT runner co-tracks 64 local support points per requested query and retains the requested point in its output. | Apache-2.0 code and the listed publisher checkpoints. TAPIR uses JAX/Haiku or PyTorch. OpenCV and torch feed TAPNext++ at 256 or 512 pixels. CUDA is the default, with a float32 CPU path. Weights, feature grids and recurrent query state add memory. Full-video offline inference can retain considerably more frame features. Benchmark only if a learned point group could improve the short gameplay occlusion cases after independent labels. The source-covered frames still have no useful target pixels. [TAPIR](https://github.com/google-deepmind/tapnet/blob/ceedd60bb9f6c9f7c74796e4445aff6c6ddf7c9b/tapnet/models/tapir_model.py), [TAPNext++](https://github.com/google-deepmind/tapnet/blob/ceedd60bb9f6c9f7c74796e4445aff6c6ddf7c9b/tapnet/tapnextpp/votsp2026/model.py) |
| SAM 2 `2b90b9f5ceec`. `sam2_video_predictor.py`, model configs and setup. | Seed an object ID with a point, box or mask. The video predictor propagates masks using conditioning memory. It can re-prompt with current pixels and clear nearby non-conditioning memory after correction. Mask strength and visible area can inform a presence check. | Apache-2.0 for upstream code and published SAM 2.1 checkpoints. Tiny is 38.9M parameters and large 224.4M, roughly 156 MB and 898 MB of raw float32 weights. Video/state offload trades RAM and speed for VRAM. PyTorch, device-specific performance and the optional CUDA extension raise integration cost. Defer unless a mask materially improves validated boxes. [Video predictor](https://github.com/facebookresearch/sam2/blob/2b90b9f5ceec907a1c18123530e92e794ad901a4/sam2/sam2_video_predictor.py) |
| Cutie `ec5cdd4cf16f`. `inference_core.py`, `memory_manager.py`, `eval_config.yaml`, `download_models.py` and `pyproject.toml`. | Object IDs keep separate sensory state. Working memory accumulates around recent masks, with optional long-term token consolidation. An empty mask is handled separately. Priors help retrieve an instance after occlusion. The app still needs a calibrated mask-presence check. The generic configuration allows 10 working-memory frames and 10,000 long-term tokens. | MIT core. The separately downloaded VOS and interactive correction checkpoints need their own license review. Torch examples use CUDA and autocast. GUI and evaluation dependencies include Qt, codecs, pycocotools and packages with native components. Windows installation and CPU latency remain unmeasured. High integration cost for this task. Defer. [Inference](https://github.com/hkchengrex/Cutie/blob/ec5cdd4cf16f75c73ad785a2f96fb97dbad4125a/cutie/inference/inference_core.py), [Memory](https://github.com/hkchengrex/Cutie/blob/ec5cdd4cf16f75c73ad785a2f96fb97dbad4125a/cutie/inference/memory_manager.py) |
| ByteTrack `d1bf0191adff`. `byte_tracker.py`, matching helpers and tests. | Kalman prediction and two association passes preserve IDs across short detection gaps. Low-score boxes can update an existing track before its lost buffer expires. The detector still supplies the visual boxes. | MIT tracker. Integrated YOLOX code and checkpoint terms are separate. CPU association is relatively small and its cost grows with box counts. A detector dominates compute and memory on this workflow. Benchmark if multiple valid detections cause confirmed ID swaps. It adds little to a single explicit subject with missing pixels. [Association](https://github.com/FoundationVision/ByteTrack/blob/d1bf0191adff59bc8fcfeaa0b33d3d1642552a99/yolox/tracker/byte_tracker.py) |
| CoTracker3 `82e02e802975`. `cotracker/predictor.py`, model build and packaging. | Joint queries use support points and windowed trajectory refinement. The offline predictor can track backward. The online path advances by half of its 16-frame window and applies a visibility and confidence decision. | The publisher uses CC BY-NC 4.0. PyTorch CUDA is recommended. CPU is possible for small tasks. Query activations and frame state grow with windows, input resolution and query count. Reference for visibility. Integration is outside the current license authorization. [Predictor](https://github.com/facebookresearch/co-tracker/blob/82e02e8029753ad4ef13cf06be7f4fc5facdda4d/cotracker/predictor.py), [License](https://github.com/facebookresearch/co-tracker/blob/82e02e8029753ad4ef13cf06be7f4fc5facdda4d/LICENSE.md) |
| SAM 3 and 3.1 `eef6839bcfc3`. Base and multiplex predictors, multiplex tracking, tests and manifest. | Prompted objects have IDs and propagated masks. The multiplex path groups objects and has a confirmation state that holds back unconfirmed masklets. Corrections and resets update the inference session. Presence evidence still depends on the visible stream. | The SAM License covers code and weights and takes precedence over the package's MIT classifier. The project documents a CUDA 12.6+ setup and gated checkpoints. Encoded frames, masklets, per-object state and model weights add memory. This gate has no local throughput or VRAM measurement. Defer. [Multiplex tracking](https://github.com/facebookresearch/sam3/blob/eef6839bcfc3458dd52ea80535dc6bd62aea86b1/sam3/model/sam3_multiplex_tracking.py), [License](https://github.com/facebookresearch/sam3/blob/eef6839bcfc3458dd52ea80535dc6bd62aea86b1/LICENSE) |
| OpenCV VitTrack. Zoo snapshot `d4938dfc9d4e`, wrapper and OpenCV `tracker_vit.cpp`. | Compares a seeded template to a search crop with a compact transformer and returns a match score. It works with the existing OpenCV DNN CPU backend. The score is evidence of appearance similarity rather than proof of identity. | The pinned model directory grants Apache-2.0. Model size 714,726 bytes, SHA-256 `2990f0b7cd44d92afa48cd97db6de7be113fc1d9594fddb74e2725c10478e91d`. The same initial Nightcrawler seed yielded 10 accepted updates and 210 misses with a .52 score cutoff, in addition to 79 masked samples. Jay3 had 19 accepted updates and 242 misses with two reviewed seeds. The probe used archived source masks and no rendered advantages. It did not sustain either track. Keep it out of the runtime. [Pinned model and license](https://huggingface.co/opencv/opencv_zoo/tree/d4938dfc9d4ec5d098bfa33e98b3f3345a236586/models/object_tracking_vittrack), [Implementation](https://github.com/opencv/opencv/blob/7a8d99e6b2253d32d8746f74a8f9805eee9c0c52/modules/video/src/tracking/tracker_vit.cpp) |

The initial optical-flow run lost the single-seeded Nightcrawler torso after its first observation. 33 ms and 17 ms sampling gave only brief recovery. Relaxing the inlier ratio or adding bounded SIFT matching did not sustain tracking across the fast pose changes. Keep the conservative 50 ms policy for the prototype and retain the user's option to supply later, source-verified anchors. A further model benchmark should focus on a real, visibly unobscured recovery failure with labels held out from that experiment.
