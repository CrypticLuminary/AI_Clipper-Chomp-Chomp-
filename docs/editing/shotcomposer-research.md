Remotion's current linked [v4 terms](https://www.remotion.dev/docs/terms-4-0) refer to a separate software license. The [terms landing page](https://www.remotion.dev/docs/terms) now describes upcoming v5 terms and explicitly distinguishes source-available software from OSI open source. Do not cite the upcoming document as if it governed the pinned v4 dependency. No Remotion integration is proposed.

FFmpeg remains the renderer. Official [blend documentation](https://ffmpeg.org/ffmpeg-filters.html#blend) describes mixing two streams with per-frame expressions; the frame index `N` starts at zero. [Timeline editing and framesync](https://ffmpeg.org/ffmpeg-filters.html#Timeline-editing) provide the execution primitives. Our chosen graph is an inference/design using those documented primitives, not a demonstrated temporal result. Actual frame-ID/audio-pulse verification is still required. Calling an existing FFmpeg binary does not settle licensing obligations if the project later distributes FFmpeg/libx264 builds.

## Editing pattern research

The user-authorized reference files remain in Downloads. The existing contact sheets were reused, without generating new ones or watching complete clips. This session directly inspected `shorts-atlas-1.jpg`, `shorts-atlas-4.jpg` and Jay3 `sample-006.jpg`. Other patterns below are design hypotheses or prior-session observations, labelled accordingly. None establishes pacing, audio quality or exact cut times from full playback.

| Pattern | Evidence level and lesson | Director vocabulary and constraints |
| --- | --- | --- |
| Hold a reaction pane while action changes | Observed four CaseOh samples per reference in atlas 1. A camera slot stays available while a reveal/object/game scene changes. | Split with independent slots; protect the reveal/object separately from a loose action search window. No requirement to zoom. |
| Preserve the actual container while a face leaves view | Atlas 1's 17.94s CaseOh sample has the camera scene/chair rather than a detected face. A missed face is not evidence that the container disappeared. | Interval-reviewed container, optional reaction emphasis only when the person is actually visible. |
| Evidence plus persistent commentator | Atlas 4 shows Tyler1/presenter and board above Emiru at 2.98/10.43/17.88s; board occupies the upper view at 24.74s. | `streamer_evidence`, then an intentional detail view while holding the reactor slot. Protect board text. Screenshots do not prove exact switch time. |
| Source-covered gameplay needs an editorial choice | Jay3 at 76,100ms visibly shows a large source webcam and narrow source game strip. All three old outputs retain a large low-information lower pane. | Propose a source-grounded streamer shot and reviewed return. The still does not authorize a particular interval or prove gameplay absence throughout it. |
| Cause → reaction → return | Previous phase's Emiru catalog reports split and reaction close-up samples. Full playback not repeated here. | Explicit ordered shots with continuity of the selected original audio. Require current source regions for the reaction and return. |
| Multi-person punchline | Design hypothesis informed by VerticalMaker and PodSwitch source, not new raw-media review. | Stable two-person stack or speaker single, then a shared response. Audio speaker ID alone cannot bind a face. |
| IRL hands/action before face | Prior phase's Speed/prop sample catalog, not re-viewed this session. | One full/source/person view plus required hands/prop/context geometry. Avoid obligatory webcam layouts. |
| Tutorial detail or commentary proof | Design hypothesis using the evidence-panel grammar. | `object_focus` or large screen-evidence slot; outline only with real target geometry and readability limits. |
| Comedy pause / quiet discovery | Editorial design principle, not a new scored example. | Deliberate hold can win. No mandatory edit cadence, effects quota or reaction cut. |
| Replay, freeze, slow motion, montage | Future vocabulary, not implemented here. | FX05 time-map/audio owner. FX03 reports delegated requests instead of pretending to execute them. |
| Kinetic text / sound punctuation | Future vocabulary, not implemented here. | FX04 captions/text and FX05 sound, licensed assets and separate validation. |

Reference videos/contact sheets are private research inputs. Do not commit or redistribute them. No precise reaction times or semantic event claims were manufactured from their filenames.

## Dependency/branch reality

Local branches inspected: Director `f187fd107ee0abd9a67a2dba14bf9466d42231ae`, StableCamera `220acdba0b4ea21fe972e0c4f18a79f47a67af53`, SubjectLock `8dd1cb52634c4eb7dd639499a4eda5b4a4709d77`, Bridge `1e7e9222cd8e73909a4a2dd511b1701dee1eea7e`. GitHub metadata confirms [Bridge #8](https://github.com/CrypticLuminary/AI_Clipper-Chomp-Chomp-/pull/8) and [SubjectLock #9](https://github.com/CrypticLuminary/AI_Clipper-Chomp-Chomp-/pull/9) open, draft and unmerged at research time. The supplied report's FX02 e605ec2 is superseded by the documentation-only 8dd1cb5 commit. Do not rebase to main or claim either PR merged.

`media.py` provides four layouts, continuous selected audio, captions/hooks, sound cues, temporary/staged files, FFmpeg validation and crop paths. `clipwork.py` saves v0.5 plans and hashes. `manual.py` preserves old rerenders. `reframe.py`, `camera_motion.py`, `subject_lock.py` and `subject_view.py` own detection/tracking/smoothing. Director `contract.py` already validates storyline and sampled-frame references, but the previous experiment path did not render that storyboard. The new native ShotPlan and controller binding adapter fill that execution gap.

The first compositor benchmark identified excess filtering because every view ran for the full clip. The final design bounds each view to its active frames and composes overlaps only for same-source dissolves. The continuation records the performance comparison. Runtime dependencies are Python, FFmpeg and the existing optional `jsonschema` Director extra.
