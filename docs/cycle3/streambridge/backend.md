## Platform capabilities

| Official operation | Credential and behavior |
| --- | --- |
| YouTube `videos.list` | API key for public reads or user OAuth where authorized. Requests snippet, content details, live details and status. Empty items indicate an unavailable ID, and the response may hide API fields for private or region-limited content. Archived broadcasts use their actual start/end when supplied, while live duration is unknown. [Videos list](https://developers.google.com/youtube/data/reference/rest/v3/videos/list) |
| YouTube `liveBroadcasts.list`, `liveChatMessages.list` | Authorized creator broadcast and bounded live chat reads using OAuth. Honor `pollingIntervalMillis` and stop if chat ends. Chat-disabled, chat-ended, missing, unauthorized and rate-limit responses can prevent further reads. Chat is process output and does not persist by default. [Broadcasts](https://developers.google.com/youtube/data/live/reference/rest/v3/liveBroadcasts/list) · [Live chat](https://developers.google.com/youtube/data/live/reference/rest/v3/liveChatMessages/list) |
| YouTube IFrame Player API | Return its official script and video ID, and optionally bind the website origin to the embed. Respect the embeddability flag, browser API and player rules, including visible attribution, controls and a minimum 200×200 player viewport. Content is displayed through the official player. [IFrame API](https://developers.google.com/youtube/iframe_api_reference) · [Developer policies](https://developers.google.com/youtube/terms/developer-policies) |
| Twitch OAuth, Get Videos, Get Users, Get Channel Information, Get Streams, Get Clips | Use a valid app or user OAuth token and matching client ID. Validate on first use and at most an hour later on reuse, or sooner when the token expires. An offline stream differs from a missing channel. Tokens can be invalidated by a 401. [Token validation](https://dev.twitch.tv/docs/authentication/validate-tokens/) · [Helix API reference](https://dev.twitch.tv/docs/api/reference/) |
| Twitch `GET /helix/clips/downloads`, `POST /helix/videos/clips` | Use a scoped user access token with the operator as editor or broadcaster. The broadcaster can use `channel:manage:clips`. Editors use `editor:manage:clips`, and Helix verifies channel authorization. StreamBridge uses the user-token flow. Clip restrictions or missing media can result in 403, 404 or missing downloadable variants. Never infer readiness from the native write's 202 alone. [Twitch Clips](https://dev.twitch.tv/docs/api/reference/#get-clips-download) · [Create Clip From VOD](https://dev.twitch.tv/docs/api/reference/#create-clip-from-vod) |
| Twitch video and clip embeds | Supply a valid website `parent` and use the returned player source URI. Twitch documents a 400×300 minimum. [Twitch embeddings](https://dev.twitch.tv/docs/embed/video-and-clips/) |

YouTube exposes neither the creator's editable video file nor a native clip write through these APIs. Work on creator-provided originals obtained independently of the platform service. YouTube restricts storing or refreshing API data, and unauthorized YouTube audiovisual downloads are outside this integration. The persistent job and review files carry references and omit provider metadata bodies. A future multi-user site should continue to fetch on demand or separately implement required consent, expiry and revocation handling. [YouTube developer policies](https://developers.google.com/youtube/terms/developer-policies)

## Python interface for LP05 and ClipControl LP03

- `source.resolve(input)` returns a `Source`. Use `platforms.inspect(source)` to obtain `(Source, error)`. Call `source.embed(source, parent=..., origin=...)` for player configuration.
- `acquire.acquire(input, root, rights_ref=..., confirmed=..., media_file=... | media_url=..., progress=...)` returns an `Acquired`. A registered Twitch clip can use `twitch_download=True`. Progress callbacks receive `chomp-source-job/1` state. `acquire.Jobs(root).status(id)` and `.cancel(id)` share that job store. `acquire.reopen(...)` expects the same normalized source identity and verifies the stored media. For a local source, use the content ID from the receipt.
- `workflow.process_acquired(acquired, output, rights_ref=..., evolution=EvolutionConfig(...), limit=..., profile=..., ...)` passes source identity and clocks to the existing processing pipeline. The source link tags candidate ledgers, edit specs and review queues. Existing local job/config paths work directly. Supply campaign/slot, duration, output layout and audio parameters through the existing engine entry points. No parallel copy of ClipControl's policy is needed.
- `live.run_live(..., options=LiveOptions(...), progress=...)` runs a blocking capture worker. `live.monitor_live(...)` provides metadata-only status. The live job returns pending and ready lists with epoch and clock source. Start jobs outside the application request thread and pass a job ID for cancellation.
- `BridgeError.public()` returns `code`, `message`, `http_status` and `retry_after_seconds`. Resolved identities can have `metadata_status=missing_credentials` with usable playback configuration. `media_unavailable`, `unauthorized`, `rate_limited`, `integrity_error` and `cancelled` are separate failure states.

The backend receives trusted local file paths from the desktop operator. In a multi-user site, resolve uploaded media IDs server-side within the user's private job root. Keep acquisition and token operations on the backend. Render provider titles or chat using text APIs rather than raw HTML. Place a separate explicit consent boundary before native Twitch POSTs.

Remote acquisition requires HTTPS, validates all DNS answers and redirect hops, and connects to validated public IPs with origin TLS hostname verification. Public platform delivery origins used for watch playback are excluded from the generic creator-media path. Native Twitch downloads are handed off only from the authenticated endpoint and constrained to supported CDN hosts. Credentials and full signed URLs stay out of job files and remote exception messages. Byte limits, free-space reserves, timeout, file checks and cancellation apply during transfer. Run media parsing on a restricted worker for a public multi-tenant deployment.

## Verification and limits

The Windows suite passed **430 tests** in 71.11 seconds, including **40 StreamBridge cases**.

- Live YouTube Data API reads succeeded with a supplied burner key. They classified public archive records and produced official player configuration. Test calls retained no API key in the workspace. An additional production live-status monitoring invocation was blocked by the execution environment. Live-status evaluation and the monitor worker were verified with controlled responses. Twitch live reads, OAuth YouTube chat and native Twitch writes/downloads were exercised with controlled API responses. No Twitch credential or authorized live chat token was available.
- On the same authorized 120-second private local excerpt used for EVOLUTION, StreamBridge acquired and reopened the original, processed the frozen transcript and rendered one 540×960 clip with playable audio. The source digest and 3.25–47.95 s interval were preserved in review. The media stayed local.
- A generated 46-second feed was ingested as eight TS chunks with local CPU Whisper. Clock validation caught an earlier 445 ms drift from including AAC padding in chunk durations. The video clock produced a final 46,000 ms, and the run rendered one 22-second preview. Chunk-local ASR did not fully recover the earliest story setup. Human editorial review remains necessary.
- Controlled tests cover reconnect after a disconnect, missing sequence/unknown gap duration, delayed finalization, a forbidden encrypted playlist, expired and missing tokens, rate limits, upload identity, interrupted downloads, cancellation and verified cache reuse.
- This first live path is a local worker for small feeds. HLS master playlists, CMAF/fMP4, low-latency partials, RTMP/SRT capture, process restart into an existing capture, and live audio-only acceleration are deferred. Windows run results do not establish multi-hour performance. Visual sampling remains enabled on analyzed live windows. Segments are already creator-authorized when they reach this service. When visual semantics or incremental ASR are insufficient, the worker can abstain.

For verification use `uv run --inexact pytest -q`. To generate a source, use the existing EVOLUTION fixture script, then FFmpeg's segment muxer with completed MPEG-TS files. For a local replay, create the `END` sentinel after writing all chunks.
